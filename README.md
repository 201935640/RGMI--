# 疾视 V2.0 项目 3 人独立协作开发指南

## 一、 全局统一规范（全员必须遵守）

### 1. 接口统一规范

- **Base URL:** `/api/v2/`

- **请求/响应格式:** `Content-Type: application/json`

- **通用响应体:** 

  ```json
  { "code": 200, "status": "success", "data": {}, "msg": "" }
  ```

- **错误码:** `400` (参数错), `401` (无权限), `500` (模型服务异常/计算超时)。

### 2. 前端规范

- **命名空间:** 页面组件存放在 `src/pages/`，公共组件存放在 `src/components/`。
- **命名规范:** 组件使用 PascalCase（如 `NetworkVisualizer.tsx`），路由使用 kebab-case（如 `/predict-ggi`）。
- **状态管理:** 统一使用 `Zustand` 进行全局状态存储（疾病 ID、预测结果缓存）。

### 3. 模型规范

- **文件路径:** `models/v2/`
- **统一接口:** 必须包含 `InferenceEngine` 类，入口函数为 `predict(input_data: dict) -> dict`。
- **输入维度:** 基因/疾病嵌入向量固定为 128 维。

### 4. 数据库规范

- **命名:** 小写下划线（如 `predict_history`）。
- **字段:** 必须包含 `id` (PK), `created_at`, `updated_at`。
- **关联:** 使用 `gene_id` (Varchar 50) 和 `disease_id` (Varchar 50) 作为逻辑外键。

### 5. 联调约定

- **Mock:** 人员 C 必须在 Day 2 提供所有 API 的静态 Mock 返回。
- **加载态:** 所有异步请求必须通过人员 A 的 `GlobalLoading` 组件反馈。

## 五、 整合审查表（防止跑偏用）

### 1. 每日必查点

- **前端：** 页面是否符合 2.5D 科技蓝风格？D3 渲染是否有卡顿？响应式是否在 375px 下正常？
-**模型：预测分值是否在[0, 1]之间？推理延迟是否超过 500ms？Embedding 维度是否对齐？
- **后端：** 接口字段是否与 Day 2 约定的 Mock 一致？Redis 缓存是否生效？

### 2. 一致性审查清单

- [ ] 所有接口返回格式是否包含 `code`, `status`, `data`？
- [ ] 前端调用 `gene_id` 时，后端返回的字段名是否也是 `gene_id`？
- [ ] 模型输出的虚线（预测）在前端 D3 中是否正确渲染为 `stroke-dasharray`？

### 3. 风险禁止行为

- **严禁：** 私自修改数据库字段名而不通知其他成员。
- **严禁：** 在前端代码中直接写死后端 IP，必须使用 `process.env.API_URL`。
- **严禁：** 模型 B 私自更改推理函数的入参格式。
